========================================================
人机协作改进措施（学习版）
用户侧 / AI 侧 具体动作清单
整理日期：2026-09-28
来源：本项目 10 份会话导出 + 培训功能 122 轮会话复盘，非通用理论
========================================================


【总纲】

把验收权抢回来，把会话纪律立起来。
规则已经够多了，缺的是执行。


【两个根因，其余都是表象】

1. 验收权在 AI 手里
   它自己定义"完成"，你用"还是不行"来验收。
   这是所有返工的源头：地图黑框、通勤页 0/114、
   "快照已生效"但批量路线根本没跑。

2. 没有会话纪律
   一件事开两个会话、同一条指令连发五遍、
   一个会话从模板日期滚到 58 采集再滚到地图重写。
   失败方案堆在上下文里，AI 越改越歪。


========================================================
一、用户侧：只做 4 件事
========================================================

【做 1】每条开工指令必须带验收命令
   写清：跑什么命令、看到什么数字/现象算完成。
   写不出来 = 你自己没想清楚，先别发。

   反面：「继续」「看看」「核实一下」「能不能快点」
   正面（你自己写过的）：
     "先查清为什么通勤页只显示 1/1：沿 抓取结果 →
      plan.candidates → 条件筛选 → 达标房源 → 地图 props
      完整追踪；禁止把当前选中房源当成全量房源。"

   指令模板（一次发完，不挤牙膏）：
     ------------------------------------------------
     目标：<一句话做什么>
     范围：只动 <文件/目录>；禁止碰 <文件/目录>
     验收：<跑什么命令，看到什么数字算完成>
     禁止：改配置 / 建库建表 / 提交 / 推送 / 改无关文件
     止损：同一问题 2 次没进展 → 停，说"卡在 X，需要你给 Y"
     产出：结论 ≤5 行，不要分节长报告
     ------------------------------------------------

【做 2】一件事一个会话，不双发、不并行写文件
   只读咨询可以并行；会写文件的会话必须串行。
   实测代价：同一条"继续收口前端"间隔 2 分钟发进两个会话
   → 两个 AI 同时改同 4 个文件 → 一个会话 12 次调用零产出，
   另一个被迫整文件重读 780 行。

【做 3】授权一次给全，别等 AI 一次一问
   开工就声明白名单：
     "本轮可以：改 src/、跑 tsc、起本地服务；
      不可以：改配置、建库建表、提交、推送、动非本项目文件。"
   反面：培训会话里测试库权限、能否建账号、能否改 system 模块，
   全是 AI 问一次你回一个字，节奏被它牵着走。

【做 4】两次纠正还不成 → 新开会话重来
   失败方案会污染上下文，继续磨只会越改越歪。
   重开时把学到的写进新指令（不是原样重发）。


【不做清单】
   x 「继续」「核实一下」「看看」——无验收标准的任务
   x 同一条指令连发多次 / 发进多个会话
   x 纯截图零文字（「这对吗？」）——AI 只能反推
   x 只贴报错中间段（Caused by 必须贴到底）
   x 情绪催促：「能不能快点啊！！！！！」
     换成事实：「这一步超过 3 分钟就停，说你卡在哪」
   x 把 AI 的报告贴给另一个 AI 解读（3 跳链路，每跳丢现场）


========================================================
二、AI 侧：只守 4 条
========================================================

【守 1】输出 ≤5 行 + 附证据
   必须列出：实际跑过的命令 + 实际输出。
   禁止「刷新页面看即可」「你自己跑更快」当交付
   ——一边这么说，一边自己占着 3000 端口让人 EADDRINUSE。
   禁止"值得表扬的部分""完美"这类自评语。

【守 2】第一轮并行探测，阻塞两次即上报
   开局把所有独立的 Read / grep / Bash 一次性发出，
   禁止"发现一个线索 → 再查一层"的挤牙膏。
   同一问题 2 次无进展 → 一句话说"卡在 X，需要你给 Y"，
   然后停手。
   禁止：为删一个空文件夹手写 NT 句柄表扫描器（实测 9 分钟零贡献）；
   授权"缺表先问我"却一次性建 146 张表；
   JUnit 起不来就转去做代理策略实验。

【守 3】不越界
   未显式授权不做：改配置、建库建表、动禁止目录、
   顺手改无关文件、提交 / 推送、写用户级全局文件。
   实测代价：红线"别碰后端"下仍改 server/config.ts、geo.ts，
   还把另一个 agent 未提交的改动一起 commit。

【守 4】完成 = 跑通用户关心的链路
   不是 tsc 通过，不是"看起来对"。
   数据问题的第一动作是直连重放 API，不是读前端代码
   （实测绕了 6 轮才走到这一步）。
   汇报数字必须能加总自洽；改口必须标"更正：上条 X 应为 Y"。


========================================================
三、发指令前 5 秒自检
========================================================

   [ ] 验收命令写了吗？（没写 → 补，否则别发）
   [ ] 范围和禁止项写了吗？
   [ ] 报错贴到底了吗（最后一个 Caused by）？
   [ ] 环境事实带了吗（端口 / 分支 / profile / 库名 / 绝对路径）？
   [ ] 这条指令会被我重复发吗？（会 → 先想清楚再发一次）


========================================================
四、唯一衡量指标
========================================================

   两个数：
     1. 每个任务的对话轮数
     2. 你打回"还是不行"的次数

   这两个数降下来就是赢。降不下来，加多少规则都没用。
   别再写新的规则文档了。


========================================================
五、本机可用性提醒（重要）
========================================================

   主力工具是 ZCode / WorkBuddy，不是 Claude Code CLI。
   网上那套斜杠命令大半不存在：

     /clear      → 无 → 用【新开会话】
     /compact    → 无 → 新开会话 + 手写关键事实粘进去
     /rewind     → 无 → 用 git commit 当检查点
     plan mode   → 无 → 指令里写"先只读出方案，等我确认再改"
     hooks/权限  → 无 → 只能用 AGENTS.md 文字规则（弱约束）

   真正能落地的硬手段只有三个：
     指令模板 / git 检查点 / 会话隔离
